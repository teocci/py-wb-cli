# Phase I-22 — `wb finance` (Sales & Acquiring Settlement Reports)

**Version:** 0.43.0 · **Status:** ✅ DONE · **Date:** 2026-05-27 · **Tests:** 1520 passing (49 new); same 2 pre-existing failures — `test_auth_list_empty` env-leak and a timing-sensitive `test_acquire_after_window_clears_no_sleep` flake that passes in isolation

## Goal

Surface six WB Finance API endpoints (`finance-api.wildberries.ru`) as a new `wb finance` command group. These are the **settlement reports** WB generates against the seller — the weekly statements that say "WB sold these items, here's what we owe you after logistics/storage/acquiring fees." They are pre-generated by WB on a fixed schedule (weekly default, daily if opted in); these endpoints are pure read-only views.

| Endpoint | Method | CLI command |
|----------|--------|-------------|
| `/api/finance/v1/sales-reports/list` | POST | `wb finance sales-reports list --from --to [--period] [--limit] [--offset]` |
| `/api/finance/v1/sales-reports/detailed/{reportId}` | POST | `wb finance sales-reports get <reportId> [--all] [--limit]` |
| `/api/finance/v1/sales-reports/detailed` | POST | `wb finance sales-reports detailed --from --to [--period] [--all] [--limit]` |
| `/api/finance/v1/acquiring/list` | POST | `wb finance acquiring list --from --to [--limit] [--offset]` |
| `/api/finance/v1/acquiring/detailed/{reportId}` | POST | `wb finance acquiring get <reportId> [--all] [--limit]` |
| `/api/finance/v1/acquiring/detailed` | POST | `wb finance acquiring detailed --from --to [--all] [--limit]` |

## Why now

User question on 2026-05-26: *"the financial report is not implemented … remember the wb CLI tool allows AI Agents to get as much information as possible from WB."* Today the agent surface covers ad spend (`wb stats`, `wb stats daily-report`), sale events (`wb report sales`/`orders`), and the ad-account deposit (`wb budget balance`) — but not the settlement layer where WB actually pays the seller. This phase closes that gap.

## Distinctions (avoid name collisions)

| CLI | Source | What it means |
|-----|--------|---------------|
| `wb budget balance` | `/adv/v1/balance` (promotion) | Ad deposit — money pre-funded for ad campaigns |
| `wb report sales` | `/api/v1/supplier/sales` (statistics) | Per-sale transaction log (saleID, finishedPrice…) |
| `wb finance sales-reports …` | `/api/finance/v1/sales-reports/*` (finance) | **Settlement statements** — what WB owes after fees |
| `wb finance acquiring …` | `/api/finance/v1/acquiring/*` (finance) | Acquiring (card-processing) fee breakdown |

## Notes for AI agents

- **No "generate" step.** WB pre-generates reports weekly (or daily if opted in). `list` discovers them; `detailed`/`get` reads line items. Date filters apply to the **reporting period** (`dateFrom`/`dateTo`), not the report creation date.
- **`--all` is opt-in.** Default returns the first page (up to 100k rows). `--all` exhausts the `rrdId` cursor and respects the 1 req/min throttle — expect ≥1 minute per 100k rows.
- **`reportId` is int64.** Python and the CLI's JSON output preserve precision natively.
